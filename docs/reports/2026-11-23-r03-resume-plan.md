### 0.2 对齐判据：以正常用户的正常使用为准（2026-11-24 用户确认）

**本节只规定 Vue 对齐 React 时要做到什么程度。React 是参照，不因本节修改 React 代码；所有落地调整都在 Vue 一侧（`frontend-vue/` 的文档、守卫、对比测试与基线数据）。**

用户说明：本产品的用户主要用鼠标操作。**总判据是：影响正常用户正常使用的才要求 Vue 与 React 对齐；不影响的不再作为对齐要求。** 这一条取代此前“语义 DOM、键盘和焦点行为逐项相同”的严格判据，适用于对齐计划的全部条目和原 R04–R12。

**要对齐：**

- 功能是否存在、操作流程、看得见的界面与文案、交互结果（点了之后发生什么）、出错提示、数据与权限是否正确。
- 发往后端的请求（11-24 用户补充确认）：请求时机、顺序、请求体、请求头、是否多发或重复发，两端要一致。
- 用户能感觉到的焦点行为：发送、切换对话、新建对话后，输入框里仍有光标、能直接接着打字；对话框打开后能直接输入，Esc 能关闭、回车能确认；按钮和链接用鼠标点得到，没有被遮挡或失效。

**不再作为对齐要求：**

- 读屏软件读到的内容与无障碍树结构（可访问名逐字相同、层级相同、`aria-*` 状态相同）。
- 纯键盘行为：Tab 顺序、关闭对话框或面板后焦点回到原按钮、焦点被困在某个面板里。
- 看不出来的像素级几何差异，以及源码写法不同但行为一致之处。

**边界：** 时序或焦点上的差异，只要让用户看到不同的结果（数据没刷新、多弹一次报错、明显变慢、打字丢了），仍然要对齐。请求本身不论用户是否看得出，都要对齐。

**落地调整**（`docs/ai/README.md` 已改；其余列在对齐计划 P0）：`frontend-vue/ARCHITECTURE.md` 的对齐范围按本判据改写；跨端对比测试的 aria 树、Tab 顺序、焦点落点几档降为参考，**请求档照常计入**；只为“读屏/键盘逐项一致”而存在的 Vue 守卫与用例逐个判断保留、放宽或删除，会影响鼠标用户的不删。

#### 0.2.1 范围清单（2026-11-24 用户逐项确认）

**使用面：全部保留。** 电脑、手机、平板三种布局都要对齐；中文和英文都要；浅色和深色都要。

**新增豁免：Showcase 公开回放页**（`/showcase/[thread_id]` 及其演示对话）。用户不用，与落地页、docs/blog、整站静态模式同等豁免。落地时更新 `frontend-vue/baseline/react-parity-scope.json` 与 `parity-scenario-coverage.json`（showcase 场景移入 exempt），并改写该 JSON 里“showcase 在对齐范围内”的说明。

**去掉（不再作为对齐要求或验收义务）：**

1. 读屏内容、无障碍树结构、`aria-*` 状态逐项相同；Tab 顺序、关闭后焦点回原按钮、焦点被困（第 0.2 节）。
2. 身份观测的**穷举证明部分**：T01–T18 边界矩阵、活动 SSE 夹具、multipart 上传归属边界等把各种极端情况逐一证明的工程。**身份对应本身保留**：已有的观测接线（`run.bind` / replay / 上传额度等事件，默认关闭、不影响产品）、身份注册表与回执，用于在请求逐项比对时把两端各自生成的随机 ID（用户消息 ID、幂等键、运行 ID 等）对应起来；不得用抹掉动态 ID 的方式比对。对齐计划第 6.1 节核实对应链路是否足够支撑请求档比对，缺的部分补齐。**其中发现的真实产品缺陷修复保留**（重复创建运行、旧草稿复现、跨对话或跨账户串数据），按普通缺陷验证。
3. 像素与几何档：逐图比对、人工审图矩阵、Linux 正式 visual（R07）。改为“肉眼看得出的界面差异”抽查，抽查覆盖三种布局、两种语言、两种主题。
4. 对照台账“零差异”目标及其逐档字段要求。
5. 200% 文字缩放、浏览器高倍缩放下的重排；“减少动态效果”下的动画与循环动画逐项基线。正常窗口尺寸与正常缩放保留。
6. 文档数字守卫：`doc-facts` 的计数类断言、`upstream-citations` 的上游行数、`doc-references` 中只为文档措辞存在的检查。
7. 证据冻结体系：源码哈希回执、manifest、每轮独立复核、外接盘证据归档。改为把实际执行的命令与结果记进对齐计划。

**放宽：**

8. “React 没有的 Vue 不许有”：放宽为 Vue 不新增用户可见的功能或文案差异；用户看不见的内部差异不再算违规。
