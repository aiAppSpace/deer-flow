# Query policy 对齐与旧 MCP owner 退役（Stage 37）

以本轮实际 React/Vue 源码、生产 QueryClient 和真实挂载计数为准。此报告只声明本域单测、类型、静态检查；最终浏览器、独立安装、完整聚合和入口验收由根任务统一重新运行，旧 Docker/Linux/入口 PASS 不代表此次源变更后的 PASS。

## 根因与修复

React 的实际 QueryClient provider 只覆盖 retry：仅原生 TypeError 传输失败最多重试三次；未覆盖 TanStack 的 stale-on-focus、staleTime 0 和 stale-on-mount 默认值。Vue 同一 retry 判据之外，额外全局关闭了焦点刷新，Agent list / Memory 又单独关闭 retry/focus，skills 单独关闭 focus。因此已挂载页面返回可见状态时，Agent、Memory、feature、MCP 等会继续显示旧数据。两端实际 QueryClient 均不应自动重试普通 HTTP 错误；models 是 React 明确规定的局部例外。

本轮删除 Vue 全局 focus=false，沿用 TanStack 默认值；删除 Agents/Memory/Skills 的错误局部覆盖，Lark status 恢复生产默认 transport retry。同时把必须保留的 React 局部例外写回对应 owner，避免全局修复引入反向差异：

- Thread list focus=false；token usage focus=false/retry=false，保留同 thread placeholder fence。
- Session Query focus=false，真实 UserPreferencesBoundary 独占 60 秒节流的 visibility refresh；不可用恢复 interval 与失败 streak 原样保留。
- Models 保留 focus=false、staleTime Infinity；UnauthorizedError 不重试，其他失败最多重试一次，与 React 当前 predicate 相同。
- Workspace changes 保留 focus=false/retry=false，并补缺失的五分钟 staleTime；Project detail retry=false。
- Scheduled form 的 Agent list 仍 retry=false；通过 catalog owner 的可选局部参数消费同一 key，Gallery 继承默认 transport retry，没有新增第二份 owner/cache。

## 旧 MCP owner 清理与测试迁移

旧 unscoped MCP composable 的两个 export 没有任何生产 import、调用、alias 或 barrel export；只剩其自身测试、一个 invariant guard 和过期 ARCH 描述。生产已由 MCPPluginManager 消费 useScopedMCPConfig。仅旧 owner 引用的 unscoped query key 模块也一并退役。

原 known non-admin 零 GET/PATCH、精确单 server PATCH、成功后 authoritative re-read 已迁入实际 scoped owner 的测试，明确 deployment scope 与 user ID key；原重复动作锁移到实际 MCPPluginManager 的 pending switch/edit 控件验证，仍断言一次 toggle 调用、disabled 重复点击无第二次请求意图、完成后恢复。原 scoped owner 的 personal route、scope/account change abort 和旧响应不跨 owner 写回继续保留。invariant guard 改为 scoped key/requestKey/captureWorkspaceQueryOwner，未删除该所有权断言。
