## 三处门禁盲区（这部分可能比功能更值钱）

1. **i18n 覆盖门禁的词典解析器**把跨行模板字符串里的括号数进了段名栈。
   后果是那张基线表整个按错坐标系记了几百条账——`movedByUpstream` 里 164 条
   「上游把路径拍平了」全是假象。修掉后真实缺口只有 37 条。
   *这条是补完 38 条 key 之后门禁仍然报错，才被揪出来的。*

2. **模板里用到却没导入的组件**：`vue-tsc` 和 `eslint` 双双放行，Vue 把它当未知
   HTML 元素静默渲染成空——页面上什么都没有，控制台一声不吭。

3. **script 里靠 Nuxt 自动导入的 Vue API**：生产不报错，但不经过 Nuxt 的 dom 测试
   一挂载就 `ReferenceError`——也就意味着那个组件从来没被挂载测试过。扫出 3 处。

另加两道：菜单项图标尺寸（`icon-parity` 只报「两边完全不相交」的，看不见
「调用点覆盖了 primitive 默认值」），以及页面 layout 必须显式声明。

## 最后一步抓到的真缺陷

把 `/workspace/projects/[id]` 加进对照取样面之后，真跑 e2e 当场红：

```
500 Internal Server Error: Workspace toast owner is not available.
```

根因是那个页面（我上一轮建的）**漏了 `definePageMeta({ layout: "workspace" })`**，
落到营销页外壳上，那里没有 toast owner。它从建出来那天起就是坏的，
而 `make verify` 一路全绿——因为**没有任何测试访问过那条路由**。

这也是「取样面」这件事的意义：它不验证行为对不对，它保证每一屏**至少被打开过一次**。
