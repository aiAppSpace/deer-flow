### 4d. 颜色不要在 JS 里手工解析（第四十四轮）

（不会降级成 `rgb()`）。把颜色画进 1×1 canvas 再 `getImageData` 读像素，
顺带把 alpha 合成和祖先 opacity 一起做掉。

### 4e. 钉住实验起点的动作，本身要先证明它不改变被测对象（第四十五轮）

第四十轮的判据是「起点是设计的一部分」。这一轮补上后半句：
想用 `blur()` 把焦点清回 body 来统一起点，**当场把读数弄坏**——
跨应用差异 0 → 4、同应用两跑不稳 0 → 2，因为菜单开着时 blur 会扰动
浮层自己的焦点管理，而那正是要量的东西。
**换成「比相邻关系」绕开相位漂**，比「强行统一起点」稳。

### 4f. 查竞态：CPU 降速无效，**推迟某一条响应**才是旋钮（第四十八轮）

同一个飘，两种旋钮的读数：

```
CDP CPU 降速 ×4 / ×8，32 跑        两边恒 1 次（触发与取样窗同比例变长，余量始终 ~3s）
把某一条响应推迟 300/900/2000ms    Vue 12/12 发两次、上游 16/16 全 1 次 —— 当场复现
```

**竞态住在两条并行请求的相对顺序里**，全局降速动不了这个顺序；
只有单独移动其中一条的相位才掰得动。做法：`page.addInitScript` 里包 `window.fetch`，
命中目标就 `const r = await orig(...); await sleep(D); return r;`。
⚠ 相对 URL 不能直接 `new URL()`（第一跑就栽在这）。

### 4g. 先分「谁多发」，再查「为什么」（第四十八轮）

`requestsOnly*` 是**多重集**差，`requestBodies` 是**集合**差
（`diff-entry.ts` 里有判词）。所以：

```
请求那一档多一行 + 体那一档没动  →  同一侧发了两次，体逐字相同
请求那一档多一行 + 体那一档也动  →  发了一条不一样的请求
```

扒 CI 那次红的原始日志就能同时看到这两档
（`gh api repos/<owner>/<repo>/actions/runs/<id>/attempts/1/logs` 下回来是 zip），
**比重跑一次 50 分钟的 CI 便宜得多**，而且方向一开始就定死了。

### 4h. 一条门禁只该守**一个**不变量（第五十二轮）

`content-reachable` 第一版把「内容竖着掉没了」和「固定宽度的盒子横着装不下」
混在一个断言里。进全套的第一跑：**两个应用同时红**，报出来的 4/5 条
**全是横向、而且绝大多数两边逐字相同**——**真正要守的纵向恰恰是绿的，被淹掉了。**

拆成两个断言之后：纵向不许有豁免，横向做成带读数的棘轮。
**拆轴当场还有正面收益**：`thread-list-pin#mobile-drawer` 纵横都中，
原来整个终态被纵向那条豁免盖掉，**横向那一半（165x / 304x）从来没有显形过**。

> **判词：门禁守两个不变量时，豁免其中一个会连带把另一个也关掉，而且关得无声无息。**

### 4i. `page.evaluate` 的函数，门限/配置一律**当参数传**（第五十三轮）

`survey()` 是序列化到浏览器里跑的，**闭包不到模块作用域**。
把内联的 `64` 「整理」成具名常量之后，每个终态都抛
`ReferenceError: MAX_GAP_PX is not defined`——而收集结果的数组因此**一直是空的**。

**抓到它的是那条「跑不到位清零」的反空转断言。** 没有它，这条门禁会**绿着交付**。

> **判词：反空转断言不只防应用的空转，它首先防的是门禁自己的。**
> 「门禁绿 ≠ 这屏没问题」（第三十九轮）的下一层是「**门禁绿 ≠ 门禁跑过**」。

### 4j. 只记「变了的」，会让「没变」同时覆盖两件相反的事（第五十三轮）

量「缩窗口之后浮层还在不在」时，第一版只记**发生变化**的格子。
于是「不变」同时覆盖「`1→1` 浮层扛住了」与「`0→0` 这屏压根没开过浮层」——
**含义完全相反**。改成每一格都记 `[缩前, 缩后]` 之后，才看得出那 5 格是 `N→N`。

这是第四十轮「『没量到』要和『量过、没问题』分得开」在**计数**上的同一条。

### 4k. 登记表会长**假账**，而假账和真账在表里长得一模一样（第五十四轮）

`content-reachable` 的两张表 12 行，摊开来定性之后：

```
3 行  尺子的洞   Sheet 的 `<SheetHeader className="sr-only">`，`p-4` 压过
                 `sr-only` 的 `padding:0`，盒子 32×32 而不是 1×1，
                 于是那条 `clientWidth <= 1` 的守卫一个都没拦住。
                 而 `clip: rect(0,0,0,0)` 仍然把它整个裁没——**屏幕上不画**。
8 行  真缺陷     两边同值（browser-feature 217x / integrations 41x）
1 行  真缺陷     上游单边（sidecar 70x）
```

那 3 行在表里挂了两轮，注释写着「两边逐字相同」，读数一个都没错。

⚠ **同一个洞在断点轴上也在造数**：第五十三轮那「18 个两边逐字相同的签名」里，
头一族 `Sheet 头 50y/265x ×6 @mobile` 就是这同一个 `p-4 sr-only`。
**一个尺子的洞会在你打开的每一条新轴上各造一批假读数，
而每一批看起来都像「这一轮新量到的」。**

> **判词一：「两边读数相同」证明的是两边一样，不证明那是账。**
> 一条写歪了的「跳过」分支，症状不是漏报，是**让登记表长出假账**。
>
> **判词二：往登记表里加行之前先问「它画在屏幕上吗」。** 加行是最后一步，
> 不是第一步——第五十四轮那 12 行里有 3 行本来就不该进表。

配套：那条跳过分支现在有**反空转断言**守着（命中次数回传出来断言 `> 0`）。
理由与 4i 同形——「跳过」写错了只会一次都不命中，而**那时候门禁照样绿**。

### 4l. 判变异成不成立，要看**它报了哪几行**，不是看退出码（第五十四轮）

第一次变异验证用 `--grep "^vue"`，一条都没匹配上
（Playwright 的 grep 不是从标题开头匹的）。它打的是：

```
Error: No tests found.
Error: pnpm command failed with exit status 1.
```

**退出码 1，和「变异被抓到」一模一样。** 差点就把「压根没跑」记成「验过了」。

> **判词：这是「门禁绿 ≠ 这屏没问题」（39）、「门禁绿 ≠ 门禁跑过」（53）之后的
> 第三层——「门禁红 ≠ 门禁跑过」。** 三层的解法是同一个：**读它报的内容**。

### 4m. 换布局前先算清楚 `flex-basis: 0` 在**换行**时的行为（第五十四轮）

`flex-1` = `flex: 1 1 0%`。**它的假想主尺寸是 0**，于是：

- 想靠 `flex-wrap` 让一行重排时，**带 `flex-1` 的那件永远不会把行挤满**，
  行也就永远不换——上游 sidecar 那 70x 就是这么来的（左组拿到 113px 装 183px）；
- 真换行之后，它会**落进「还剩点空的那一行」再去长剩余空间**——
  browser 工具条上实测长出来 **5px 的地址栏**。

两处的改法都是 `flex-1` → `grow basis-0`，再按需要给
`@max-[<N>rem]:basis-full`（**门限写 rem**：要随文字变大而重排，不是随窗口）。

⚠ 顺带一条：`md:` / `sm:` 这类**视口断点**和「格子里按 rem 排的内容」天生不配套。
`integrations` 那 41x 就是——四列在 200% 下还是 166px，而徽标涨到 151px。
能用 `grid-cols-[repeat(auto-fit,minmax(<N>rem,1fr))]` 就别用容器查询：
它不需要多立一个容器，也就不会给谁加上 `contain: layout`。

### 4n. 改完布局要**重新量整片**，不只量你打算改的那一处（第五十四轮）

两个 composer footer 的 `gap`：上游两个调用点都传 `gap-2`，本仓一个都没有
（scoped CSS 只实现到 `PromptInputFooter` 默认的 `gap-1` 那一层）。

**这条差异在这一轮之前量不出来**：不换行时两个组一个 `grow`、一个右对齐，
多出来的 4px 被 free space 吃掉，**外沿逐像素相同**（submit 与档位键两边 x 全等）
——台账因此一行都报不出。是这一轮**先给 sidecar footer 加了 `flex-wrap`**，
那 4px 才变成行间距现形：200% 下本仓 rowGap 8px、上游 16px。

> **判词：一条被 free space 吃掉的差异，在布局换行之前是量不出来的。
> 所以改完布局要重新量一遍整片，而不是只复量你改的那一处。**

⚠ 配套：本仓要压过 `ComposerSurface.vue` 的 scoped CSS（`(0,2,0)`）
得用 `gap-2!`——普通工具类是 `(0,1,0)`，压不过。
这是本仓已有的写法（`gap-1!` / `px-2!`），不是新发明。

### 4o. 命中测试类的尺子，先量 `pointer-events`——它是**继承**的（第五十五轮）

浮层打开时 primitive 会把整页设成不可点。实测：

```
body 的 style 属性 = "pointer-events: none; overflow: hidden;"
bodyPE=none   htmlPE=auto   每颗 button 的 computed pointerEvents = none
→ document.elementFromPoint 对**每一个点**都返回 <html>
```

所以任何靠 `elementFromPoint` 的尺子，在**所有开着浮层的终态**上都会整场失真。
那些控件确实点不动，而那是对的（判据与第四十四轮 `aria-hidden` 同形），
**要按 `getComputedStyle(el).pointerEvents === "none"` 排掉再读结论。**

⚠ **同一条继承还会把你的阳性对照一起废掉**：盖上去的遮罩是 `body` 的孩子，
自己也变成 `none`。**遮罩必须显式写 `pointer-events: auto`**，
写了才量得到 `top=div#zz-overlay`。这一轮**修好命中判据之后对照仍然报 0**，
就是栽在这后半条上。

> **判词：「点不动」有两种——被别的东西盖住，和整层被关掉。
> 尺子不分开这两种，就会把后者算成前者，或者（更糟）什么都报不出来。**

### 4p. `element.contains(topmost)` 不能反过来写（第五十五轮）

照 `capture.ts` 抄命中判据时我多写了一个 `top.contains(el)`，
而 **`body.contains(el)` 恒真**——盖住时 `elementFromPoint` 回的常常就是 body/祖先，
于是「被盖住」这一支**永远为真、永远不报**。`capture.ts` 原本只写
`element.contains(topmost)`，**是抄的时候加错的**。

> **判词：抄一条现成的判据时，多加的那半句就是你自己的假设，
> 要和新写的代码一样被对照验过。**

### 4q. 「补上对称的另一半」在两个不同构的 primitive 上可能只有一边生效（第五十五轮）

两个应用都已经在用 `max-h-(--*-content-available-height)`，
所以给菜单补 `max-w-(--*-content-available-width)` 看起来只是补齐对称。实测：

```
上游   生效：子菜单 344 → 256，条目换行到 104px 高
本仓   不生效：--reka-dropdown-menu-content-available-width 与
       --reka-popper-available-width 两个名字都试过，仍是 344
```

结果是**只有一边变了 = 当场造出一条新的两边不一致**，已整组还原。

> **判词：两边同改的前提是两边都**量**过，不是两边都**写**过。**

⚠ 顺带一条被读数否掉的推断：给上游 `DropdownMenuSubContent` 传 `sticky="always"`
**一格没动**。Radix 的 shift 配的是 `mainAxis: true, crossAxis: false`，
而 `side="right"` 的子菜单要移的是 x（cross 轴）——它根本不在那条轴上 shift。
**推断说得通，读数不认。**

### 4r. 「改了没反应」有两种，写错方向会让下一个人白跑一轮（第五十六轮）

第五十五轮给两边菜单补 `max-w-(--*-content-available-width)`，
上游变了、本仓没变，我当轮写的判词是「**本仓 reka 侧变量不生效**」。**错了。**
第五十六轮把变量直接读出来：

```
父菜单   两边都 available-width = 210px    实宽 384   maxW=none
子菜单   本仓 --reka-...-available-width  = 375px    ← 比自己的 344 还大，夹不住
         上游 --radix-...-available-width = 174px    ← 夹得住
```

**变量两边都设了、类也都应用了**，差的是两个 primitive 算出来的**值**。
另外 `min-w-32` = 8rem 在 200% 下是 256px，是个 rem 下限，**会把 `max-w` 顶回去**。

> **判词：没生效 → 去查绑定；生效了但不顶用 → 去查那个值是怎么算的、
> 以及有没有别的声明把它顶回去。把后者写成前者，下一个人会往错的方向查。**

### 4s. 一个改动要在「它没打算动的那一档」上也量（第五十六轮）

同一个 `max-w-(available)` 加在 `DropdownMenuSubContent` 上：
**200% 那一档修好了**，而**基线那一档退化**——上游子菜单被夹到 129px、
`Export as Markdown` 换行成两行（高 32→52），
于是两边基线宽度**从相同变成 181 vs 129**。整处撤回。

> **判词：拿目标那一档的好处去换别的档的退化，净值可能是负的。
> 改完两档都要量，尤其是「我没打算动它」的那一档。**

### 4t. 「有没有 X」这种结构判据，先看阴性对照报几条（第五十七轮）

`forced-colors` 那个面的第一把尺子写的是
「`border`/`outline`/`background-image` 三样都没有 = 没有边界」。
**阴性对照（普通模式）当场报出 623 / 685 条**——这个设计里大量按钮
本来就是 ghost 的，靠底色和文字区分，没边框是**正常**。

更坏的是它**照样给出了一张跨应用差异表**（16 / 60 行），
看起来很像发现——而同一张表在 normal 档就有 15 / 77 行，
**与强制配色根本无关**。

> **判词：结构判据（有没有某个属性）和体验判据（用户能不能分辨）不是一回事。
> 做对照之前先跑阴性对照：它报几百条，就说明你量的不是你想问的那件事。**
> 这是第四十四轮 4c（`aria-hidden` 那次）在另一个面上的同一条。

### 4v. 首屏预算是按**本机**设的，而 CI 系统性更重（收尾轮，CI 抓到）

`route-payload-budget.json` 的 `/login` critical 在 CI 上红了 139 B，本机是绿的：

```
本机 (macOS)  25 files / 369,534 raw / 122,205 brotli   ← 绿
CI  (Linux)   26 files / **372,139** raw / **123,465** brotli   ← 红（预算 26/372,000/123,000）
平台差        +1 file / +2,605 raw / +1,260 brotli，**系统性**
```

**这道预算历轮都按本机读数设**（预算文件里每一条 `$measured` 都是本机的），
所以它在 Linux 上**本来就几乎没有余量**。本机自 2026-09-16 那次记录以来只涨了
**306 B**（第五十四～五十八轮给两个应用加的那几条无障碍 Tailwind 任意值），
**是这 306 B 把早就贴着线的 CI 读数顶过去的**。

> **判词：把一道阈值按本机读数设，等于把平台差整个吃进余量里。
> 阈值要按**跑它的那台机器**的读数设。**

⚠ 同一条还预测了下一个雷：`/` 在本机是 29 / 398,437 / **131,046**，预算 brotli **131,200**
——按 +1,260 的平台差推，**它在 CI 上会非常接近甚至越线**。
**这是推算不是读数**；哪天 `/` 红了先照这条查，别去找代码回归。

⚠ 逼出实测值的办法（预算文件自己写着）：**把那条路由的预算压到 1，让它把 measured 打出来**。

### 4u. 「在我这台机器上装得下」不是「装得下」（第五十八轮，CI 抓到）

第五十六轮那次推送的 parity 在 **Linux** 上红了一条，而本机（macOS）全绿：

```
本机  本仓子菜单 200% 下 w=344，视口 375 —— 正好装得下
CI    同一处 w=384 —— **溢出 9px**
```

内容一模一样，`Export as Markdown` 在 Linux 的字体回退里更宽。

> **判词：内容撑开的盒子只是「刚好」够时，靠的是字体度量的运气。
> 换平台、换字体回退就破。要么给它约束，要么它是定时炸弹。**

⚠ 这也是「本机全绿 ≠ CI 绿」的一个新实例：
**字体度量是 macOS/Linux 的系统性差异**，凡是「内容宽度贴着某个边界」的读数，
本机的那一份都只能当**下界**。收工判据里那条「台账 0，macOS 与 Linux 同时」
就是为这件事写的——**它对新门禁同样成立**。

⚠ 修法上还有一条：夹这类盒子要夹**视口**（`calc(100vw-1rem)`），
不要夹 popper 的 `available-width`——后者在两个 primitive 上算法不同
（上游 174 / 本仓 375），而且**基线字号就会咬**（第五十六轮实测已撤回）。

### 5. `hidden` 断言前面必须有一条 `visible`

`locateTarget(...).first()` 匹配不到时是个**空 locator**，而
`waitFor({ state: "hidden" })` 对不存在的元素**立刻通过**。

### 6. 锚点不能写死英文

场景跑 en-US 与 zh-CN 两维。**优先挑夹具里的字符串**（`display_name`、
`mock.threads[].title`）——它不过词典，天生语言无关，而且证明的东西更强。
本轮 channels 场景的注释里已经把这条写成判词了。

### 7. 本机 `make verify` **不含** `e2e-mock`

**改动碰到布局 / primitive 时，本机要额外跑 `make e2e`**（约 2 分钟）。
⚠ **这里不再写用例数**：同一个数原本在本文件写了两处，其中一处没人维护，
2026-09-23 实测 `npx playwright test -c playwright.config.ts --list` 是
`Total: 297 tests in 44 files`，而这里写着 296。
**用例数只看「现场量一遍」那一节的基准读数块，对不上先查为什么。**

### 8. 「逐字对齐上游」不是无条件正确的

本仓比上游多出来的东西，可能正扛着上游没有的约束。
**删之前问「它在守什么」，而不是只问「上游有没有」。**
本轮的 `flex-wrap justify-end` 就是反方向的同一条：本仓多出来的那颗类
正是上游缺的那条账。

### 9. 「余量为 0」和「守住了」长得一模一样

只断言「溢出为 0」抓不到「余量为 0」。本轮 channels 在 **375px** 上的余量是 **−4**，
而 `panelOverflow` 在 375 上只有 4——**门限 12 是唯一抓得住 375 那一档的东西**。

### 10. 改 React 的 JSX 注释，别插进三元表达式的分支位置

`{cond ? ( {/* 注释 */} <X/> ) : null}` 是语法错误。注释要放在

## ⚠ 判据（历轮被订正十几次，形状只有一个）

**「说得通的东西」和读数长得一模一样。**

- **一次运行是一个样本**——判「修好了」要同一棵树连着量到稳定；判「飘」两次不一致就够；
- **推翻一次实测只能靠另一次实测**，算术和源码结构都只是线索；
- **总数不是读数**——它会被「尺子变准」和「修好差异」两个相反方向同时推动；
- **「源码一样」不等于「运行时一样」**；反过来，**「文档写过」不等于「现在还成立」**，
  但**「文件头写过并带读数」通常就是判词**，重开之前先读它；
- **「台账 0 行」不等于「这一屏对齐了」**——它还可能是两边一起采早了；
- **「门禁绿」不等于「这一屏没问题」**——它还可能是**夹具是空的**（第三十九轮实证）；
  补夹具只修了一半，**空转本身要被断言堵住**，否则它会再回来（第四十一轮）；
- **脚本改文件必须断言锚点命中**——`str.replace` 匹配不上时返回原串、不报错，
  于是你会拿着一个假前提去读后面的红（第四十一轮实证）；
- **尺子报出差异时先问：两边用户看到的东西有没有区别**——角色/几何/可达性全同、
  只差一颗内部样式钩子或只差一个时长，那是尺子的问题，不是应用的问题。
