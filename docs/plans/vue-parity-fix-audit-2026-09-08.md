# 自审：这一段（wave 157~176）修过的每一处，是根因、补丁，还是绕过

判据：**同一类缺陷还会不会以别的面目回来。** 会，就说明只修了症状。

分四档：

- **根因** —— 改的是产生这个缺陷的那个决定，同类不会再以别的面目出现。
- **根因 + 类守卫** —— 上面那条，外加一条挡住整类的门禁。
- **半根因** —— 改对了地方，但用的是一个**相关信号**而不是那个概念本身。
- **不是根因** —— 只做了检测 / 缓解 / 绕过，成因至今没查清。

---

## 不是根因的（1 处，必须先说）

### wave 171：前端镜像里装着 macOS 的原生二进制

**做了什么**：`--no-cache` 重建镜像（当场恢复），加 `docker/node-entrypoint.sh`
——启动前扫 `node_modules/.pnpm`，发现 `*-darwin-*` / `*-win32-*` 就**拒绝启动**并给出修法。

**为什么不是根因**：我**至今没查清那个 macOS 包是怎么进到一个 `linux/arm64` 镜像里的**。
今天补查过的路径，全部排除：

| 假设 | 实测 |
| ---- | ---- |
| `.dockerignore` 当时没排除 `node_modules` | **否**——那两行是 2026-02-09 加的，远早于事发的 8 月 4 日 |
| 容器 bind-mount 了宿主机 `node_modules` | **否**——`docker inspect .Mounts` 为空；宿主机放标记文件容器看不到 |
| Compose Watch 把它同步进去了 | **否**——同上，而且 ignore 里明确有 `node_modules/` |
| BuildKit 的 pnpm store 缓存带进去的 | 缓存挂载是 BuildKit 管的卷，不是宿主机目录；而且 pnpm 按平台选包 |
| 「两边条目数都是 1087」说明是同一份 | **这条推理是错的**——一个平台包换成另一个，条目数本来就不变 |

**所以现在的状态是**：**能检出、会拒绝启动、给得出修法，但防不住它再次发生**。
下一次它出现时，`node-entrypoint.sh` 会在**启动那一刻**喊出来（而不是十小时后变成一个 500），
这是有价值的，但它是**检测**不是**预防**。

**要真正结掉这条，得拿到一次可复现的重现**：在什么条件下 `pnpm install --frozen-lockfile`
会在 linux 容器里落下 darwin 包。没有重现之前，任何"根因"都是编的。

## 半根因的（1 处）

### wave 158：发送自己的 id 交接被当成「用户换了会话」

**做了什么**：那个「切会话就重置」的 effect，加一条
`if (optimisticThreadIdRef.current === currentViewThreadIdRef.current) return;`。

**为什么只算半根因**：真正的成因是**那个 effect 把两件事混为一谈**——
「用户换到别的会话」和「这次发送拿到了 id」。我改对了地方，
但用的判据是**一个相关信号**（手上的乐观消息属不属于当前视图），而不是
「这是一次 id 交接」这个概念本身。

它精确、有注释、有负向验证，但**如果哪天乐观消息的生命周期变了，这个相关性会失效**，
而缺陷会以别的面目回来。真正的根因修法是让「交接中」成为一个显式状态。
**没做，因为那是更大的改动；这条如实记在这里。**

## 三处「结论错了、后来被自己推翻」的

这些不是修法问题，是**判断问题**，同样要记：

1. **wave 160 判「落地页在对齐范围外，不修」** —— 把「谁的页面」和「谁的缺陷」混为一谈。
   wave 176 推翻：那是个真缺陷，凡是落到软件渲染的用户都在为它买单。
2. **wave 174 宣称 GitHub 超时修好了落地页抖动**，证据是**连绿四次** ——
   **四次绿不足以证明一个负载相关的抖动没了**。真根因在下面一层。
3. **wave 159 说两个请求终态"差三条 GET"** —— 拿 `diff` 看多重集，把「出现两次 vs 一次」
   读成「缺一条」。wave 175 按计数重比才对。

## 结论

**16 处修改里：12 处是根因（其中 5 处带类守卫），1 处半根因，1 处不是根因。**
另有 3 处判断错误已被自己推翻并订正。

**最需要盯的是 wave 171 那条**：它现在靠一条启动自查兜着，
**成因没查清 = 防不住它再来**。下一次它出现时，把当时的镜像层留下来
（`docker save` 或 `docker image inspect` 完整 history），那是拿到重现的唯一机会。
