# DeerFlow：跨平台、跨模型接手入口

这份指南用于 Cursor、Codex、其他编辑器或命令行中的助手接手本仓库。它只依赖仓库文件与可核验现场，不依赖某个平台的聊天记忆、工具名称或隐式权限。**先理解用户本次要讨论、审查、写文档还是恢复实现；打开项目或读取本指南不自动恢复任务。**

## 1. 新会话先读什么

按顺序读取，避免一开始加载几十万字历史：

1. 根 [AGENTS.md](../../AGENTS.md)：项目稳定规则、服务拓扑、命令归属。
2. [CURRENT_TASK.md](CURRENT_TASK.md)：当前任务的唯一入口指针、原仓/候选关系和最新文档增量。
3. 该指针列出的最新全计划交接、当前状态及本轮相关验收原件；先弄清最后接受、当前未接受、最近失败分别是什么。
4. [PROJECT_RELATIONSHIPS.md](PROJECT_RELATIONSHIPS.md)：仓内模块、上游/fork、可选外部服务和明确无关联项。
5. [RECOVERY.md](RECOVERY.md)：先选同机接手、候选丢失或换机路径，核对编辑目录、迁移材料和文档增量链。
6. 本次要改的模块指导及源码/测试；只深入与任务有关的历史提案和报告。最后才追旧轮次。

可以把 [NEW_SESSION_PROMPT.md](NEW_SESSION_PROMPT.md) 中的模板交给新平台；其中任务选项必须由用户明确填写。不能假定某个平台一定自动加载AGENTS.md；启动时显式要求读取上述入口最可靠。这里没有额外创建拼写近似的`AGENT.md`或复制一套平台规则，避免多个版本漂移。`CLAUDE.md`继续只导入根AGENTS；Copilot入口引用同一份规则。

## 2. 哪类事实放在哪个文件

| 信息 | 唯一维护位置 | 不应怎么做 |
| --- | --- | --- |
| 长期约定、monorepo地图、根命令 | 根AGENTS.md；模块细节归各模块指导 | 不把每轮测试数、临时路径塞进根规则 |
| 模块职责、状态所有权、行为合同 | React/backend各层AGENTS；Vue ARCHITECTURE/BEHAVIOR_CONTRACTS/README | 不按文件名猜业务owner，不给Vue照搬React私有实现 |
| 关联关系、外部依赖类别 | PROJECT_RELATIONSHIPS.md | 不把同目录/同机器项目推断为依赖 |
| 换平台/换机恢复与编辑目录 | RECOVERY.md | 不把历史绝对路径、旧index字节或已有依赖当作新机器前提 |
| 当前停点、最新文档入口 | CURRENT_TASK.md → 有日期的全计划交接与状态 | 不在多个入口各写一套进度 |
| 设计裁决、根因、被否决方案 | 对应有日期的提案/审查/ACCEPTANCE及原报告 | 不把旧“下一步”或旧草案直接当当前命令 |
| 执行证据 | docs/reports/evidence内冻结、命令直接退出码、日志、附件、独立复核；2026-11-23起该目录在外接盘`/Volumes/edisk/deer-flow/docs/reports/evidence/`，见CURRENT_TASK | 不覆盖旧失败，不重命名旧PASS绑定新源 |
| 凭据与机器配置 | 实际运行环境和项目既有配置机制 | 不把密钥、cookie、数据库内容写入指南/提示词/归档 |

新提交或任务收尾后，更新当前指针并生成可追溯的新交接；保留旧报告。文件职责划分比无限增加规则文件更重要。

## 3. 项目目标与裁决标准

本项目是上游DeerFlow的fork。React `frontend`是上游前端，Vue `frontend-vue`由本仓另建；Vue目标是与React的**功能、操作流程、行为、UI样式**可平替，并与backend实际REST/SSE/JSON、权限和持久化一致。Vue架构重构、历史负担清理和对齐是同一总计划中的不同工作面。

- 本期唯一内容/部署排除：Vue首页内容、docs/blog内容站、整站无后端静态模式。Showcase、完整键盘/焦点、响应式和语言/主题矩阵仍在范围内。
- 后端实际契约决定wire/auth；React实际可达行为决定参照；React真实缺陷可经证据修复，不能改React来掩盖Vue差异。Vue应使用自身框架的合理实现。
- 真实源码、直接运行结果和最新用户指令优先；历史文档用于追溯。两端同错不等于对齐，采集缺证不能当无请求/空body。
- 不以任意延时、吞错、猜字段、补偿请求、抹动态ID、扩大allowlist、删用例、改预算/阈值绕过失败。允许合理预算超出，维护性优先。
- 必要无障碍、原生键盘与公开组件适配不能凭“非核心”删除。历史清理须证明旧消费者已替代；不按删除行数衡量完成。
- 全范围、依赖源码例外和已否决方案详见当前交接；旧Streamdown表格patch等已被替代的方案不能复活。

## 4. 修改前先确认的现场

先只读检查，不擅自启动服务或大规模验收：

- 当前工作目录、branch/HEAD/main祖先关系、是否unmerged；已有tracked/untracked WIP、index、私有配置、hooks。Git状态和服务PID只能现场核验，不能信历史。
- 本次允许修改的源是在原仓还是隔离候选。**最新计划的全部成果尚未集成原仓**；只打开ROOT就可能看不到最新修复，详见CURRENT_TASK。
- 源/依赖的精确冻结及已记录的文档增量；不一致要列真实差异，不能忽略全部AGENTS/docs或重写旧manifest让校验变绿。
- 任务自有端口/进程与其他项目服务。使用前重新确认归属，不kill旧PID，不因端口冲突停止无关项目。
- 测试或构建是否还在运行；同副本`.next/.nuxt/.output`共用，不同端口不代表输出隔离。冻结验收时不并发改源。
- 只读状态、写交接与实施授权分开；提交/推送/发布/删除范围遵循用户最新明确指令。修改在哪个分支，获准提交就在该分支，不为提交另开分支。

不要运行`git reset --hard`、`git clean`、整树restore/复制来“清场”；更不能把隔离候选的缺文件当作删除原仓文件的依据。

## 5. 工具、依赖与命令：平台换了，合同不变

| 能力 | 平台无关的要求 |
| --- | --- |
| 文件搜索/源码阅读 | 用当前平台文件工具或终端；优先rg并限制输出，先查索引，避免整份旧账淹没上下文 |
| Shell/测试 | 记录cwd、完整命令、直接退出码、日志和精确源码；管道tail/grep不能替代测试退出码 |
| 浏览器验收 | 用仓库实际Playwright/Chromium门禁与指定配置；无法启动时写环境阻断，不能用截图或模型阅读替代行为验收 |
| 独立审查 | 可用已获授权的独立agent/新上下文reviewer；若平台不支持，保留未审状态并安排真实独立复审，不把主实现者自查改名独立通过 |
| 执行权限 | 历史业务授权不等于新平台拥有系统权限；遵守新平台沙箱/审批，说明实际阻断。不能绕过审批或谎称已执行 |
| 会话记忆/技能 | 不假定继承Codex记忆、skills、工具名、子代理或session ID；先查可用能力。仓库中的DeerFlow产品skills不是开发助手自动获准执行的操作指令 |

host pnpm必须从**实际要验证的工作副本根目录**调用`python3 scripts/pnpm.py --dir frontend …`或`python3 scripts/pnpm.py --dir frontend-vue …`（选择一个模块，不能把竖线写进shell命令）。当前R03产品工作目录是COPY9，ROOT保存新入口和证据；两者不能混用，详见RECOVERY。它选择目标workspace的固定package manager；不要凭全局pnpm版本改lock。当前两端packageManager为10.26.2，后续以package.json/锁文件为准。后端Python版本和uv工作区以`backend/pyproject.toml`/uv.lock为准；当前requires-python>=3.12。

恢复候选依赖按当前交接的两端`install --frozen-lockfile --strict-peer-dependencies`、backend锁与browser extra准备合同；不能复制旧node_modules充当正常安装。pnpm补丁通过项目patch文件/锁分发；不得把授权过的包泛化为任意新依赖源码修复。

根make编排整站，模块Makefile只管该模块。下面“根”指已授权的实际产品工作副本根目录，当前为COPY9；这些是恢复后的导航，**暂停期间不执行**：

| 范围 | 当前入口（阅读源码后按本轮授权执行） |
| --- | --- |
| React | 根pnpm wrapper执行`check`、`test`；详细见frontend/AGENTS.md |
| Vue | `make -C frontend-vue verify`及mock/backend/parity/visual相关目标；完整验收顺序见交接 |
| backend | backend内make test四分片、test-blocking-io、lint、格式检查；读backend/AGENTS.md |
| 本地整站 | make dev-vue / dev-dual及规定生产入口；本地React3200、Vue3100、Gateway8001 |
| Compose | 公共Nginx2026、容器内部前端3000；不能将容器端口一起改成3200 |
| 当前受控浏览器 | Vue3440、React3441、Gateway fixture8340；是验收拓扑，不是真实外部生产证明 |

具体门禁、额外契约/consumer/OpenAPI/资产、Linux/standalone/Docker/SQL/auth都在总交接，不能只跑上表几项就关闭计划。不要执行旧Copilot文档的绕过env validation建议或用旧“pnpm check失效”代替当前脚本。

## 6. 证据要怎样读、怎样写

- **实现存在**：只证明文件/接线已写；不等于测试通过。
- **PASS / FAIL**：绑定明确版本、直接exit、具体门禁范围与原件。
- **UNRUN / BLOCKED / UNOBSERVED**：未执行、环境受阻、外部未观察分开。
- **SCOPED_ACCEPTED**：限定增量及其独立复核通过；不代表R03或总计划通过。
- **历史PASS/输入桥接**：原源码上的旧结果，只能在明确精确未变输入下解释，不能说本轮重跑。
- collection只表示发现多少用例；日志行数、路径数、截图数、测试总数不能兑换为完成率。当前没有可信的加权总百分比。

交付文件至少记录：目标/范围、source/runtime/依赖版本、已改路径及原因、相关测试直接结果、原失败、未跑项/外部限制、是否集成原仓、剩余问题、下一步和持久恢复位置。停止时保留自有任务状态、必要归档、临时路径重建方法，避免只剩机器上的/tmp。

## 7. 换机器或换平台尤其容易漏的材料

本仓有大量**尚未提交的源码、文档和证据**，以及尚未确认已在远端可获得的本地提交。只clone GitHub远端、切到main-wc或打开同名目录，不保证包含当前成果。迁移前清点本地WIP、公开候选归档、所有被引用证据、最新交接/当前指针、依赖lock/patch与允许的文档增量。真实凭据走已有安全配置渠道，不装入公开源码包。

详细材料清单、Git本地历史与暂存语义、缺项处理、新路径映射见[恢复操作说明](RECOVERY.md)。同机换编辑器可使用同一绝对路径，但仍须核哈希。换机须记录新的ROOT/COPY路径并重新绑定runner/import/testDir/output/reporter/端口；旧报告中的绝对路径只作来源，不能仅换label假称复用成功。H03公共源码归档不含全部历史证据、依赖安装或私有运行数据，恢复演练未做的事实继续保留。

对话里给用户的长prompt、报告、配置、脚本和迁移说明写成持久文件，回复给绝对路径，不贴一大段可用内容夹在解释中。沟通用中文，报告真实进展与阻断；不声称后台会继续运行不存在的任务。

## 8. 接手完成的判定

新模型先用文件事实回答RECOVERY中的接手确认项，说明工作目录、当前版本/失败、完整范围、证据与下一步；用户明确恢复后再执行。仅生成一段“我已理解”不能算接手核验。若路径、证据或能力缺失，记录缺口并继续不依赖该缺口的只读工作，不伪造运行结果。

本轮只做文档内容、链接和现有文件完整性复核，**未实际在Cursor或其他平台启动新会话、未做跨机恢复/安装/浏览器演练**。因此交付的是经核对的接手材料与明确恢复流程，不是对所有编辑器/模型/系统环境的零配置运行保证；原计划继续暂停。
